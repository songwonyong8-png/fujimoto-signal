# Fujimoto Signal — iPhone PWA F9-A

이 저장소의 **아이폰 홈 화면 매매신호등**은 F3–F9 연구 결과에 맞춰 2026-10-25에 개편되었습니다.

## 실제 페이지 규칙: 연구용 F9-A, 일봉 종가 신호 / 다음 거래일 시가

| 단계 | 매수 | 물량 | 독립 매도 |
| --- | --- | ---: | --- |
| 1차 | RSI(14): 최근 5거래일 내 RSI ≤ 30, 현재 RSI 30–48, 종가 > 전일 종가 | 1/9 (11.1%) | RSI ≤ 30 재진입 |
| 2차 | 1차 신호 다음부터 20거래일 이내 MACD(12,26,9) 골든크로스, 1차 물량 보유 중 | 2/9 (22.2%) | MACD 데드크로스 |
| 3차 | 2차 신호 후 20거래일 이내 전환선 > 상승 중인 기준선, 종가 구름대 상단 상향 돌파, 현재 종가 > 26거래일 전 고가(후행스팬 확인). 1·2차 물량 보유 중 | 6/9 (66.7%) | **F9-A: 종가 구름대 하단 이탈** |

- RSI 70 익절 **사용하지 않음**, 양봉 확인 및 VP(매물대) 필터 **사용하지 않음**.
- F9-B(구름대 상단 이탈), F9-C(구름대 상단 아래 2일 연속 마감)는 **백테스트 비교용**으로만 유지합니다. 페이지 주문 판단에는 적용하지 않습니다.
- 세 단계 주문은 오늘 종가가 확정되어야 후보로 발생하며 **다음 거래일 실제 시가가 나와야 백테스트 가상 체결로 기록**됩니다. 최신 일봉의 신호를 오늘 체결했다고 표시하지 않습니다.
- **가상 전략 계좌**는 2020년 이후 가용한 가격을 토대로 F9-A 규칙을 재현합니다. 실제 증권계좌의 보유/평단/수익률을 나타내지 않습니다. 부분 청산된 단계는 같은 가상 매매 주기에서 재매수하지 않습니다. 다른 단계의 물량은 독립적으로 보유/매도합니다.
- 일봉이 7일 이상 오래되면 현재 매수/매도 안내를 보류하며 최신 데이터 갱신을 요청합니다.
- 1차 매수와 2차 추가매수 간 20일, 2차와 3차 간 20일의 제한은 **거래일 기준**입니다. 3차 이후의 보유 기간에 강제 청산일은 없습니다.

## 화면 구성

- DRAM, NVDA, MU, AMD 4개 관심 종목, 각 종목별 F9-A 단계 상태 및 현재 종가의 주문 후보.
- RSI, MACD, 일목구름 상·하단, 후행스팬 조건, 매도 무효화 기준과 최근 가상 체결 내역.
- 200종목 확장 백테스트 결과는 [F9 연구 보고서](reports/f_signal_exit_v9/report.md)에 보관됩니다. **200종목 전체를 실시간 감시하거나 200개 종목 데이터를 매일 자동 갱신하는 기능은 아닙니다.** 시장 확대와 모바일 종목검색은 별도 구현이 필요합니다.
- `CSV` 수동 업로드는 **시세 차트 미리보기 전용**입니다. 백테스트 엔진과 동일한 기술 신호를 보장할 수 없으므로 사용자 CSV로 판단한 매수/매도 신호는 의도적으로 노출하지 않습니다.

## Python과 웹의 단일 신호 엔진

- 기존 `backtest_f_v6.py`가 정확한 기술 지표를 계산합니다.
- `backtest_f_v9.py`의 **A형 매도 엔진**이 전체 가상계좌의 거래를 재현합니다.
- `signal_snapshot.py`가 마지막 일봉에서 다음 시가의 주문 후보와 lot1~3 상태를 추출합니다.
- `update_data.py`가 `data/{DRAM,NVDA,MU,AMD}.json`에 역사 OHLCV와 `strategy` JSON을 저장합니다.
- `app.js`는 이미 계산된 Python 지표/신호를 표시만 합니다. 과거 v1 이격도·점수제 판정을 수행하지 않습니다.
- `.github/workflows/daily.yml`은 미국 시장 거래 종료 뒤 평일 23:30 UTC(한국시간 다음 날 08:30) 예약 실행됩니다. Actions 지연 및 야후 시세 지연 가능성을 전제로 합니다.

## GitHub에 등록하는 방법

1. 기존 저장소 `songwonyong8-png/fujimoto-signal`의 **최상위 경로**에 이 패키지의 `index.html`, `app.js`, `sw.js`, `manifest.webmanifest`, `update_data.py`, `signal_snapshot.py`, `test_signal_snapshot.py`, `README.md`를 **동일 이름으로 덮어쓰기** 합니다. 기존의 `backtest_f_v6.py`, `backtest_f_v9.py` 등 연구 파일은 변경할 필요가 없습니다.
2. `.github/workflows/daily.yml` 파일을 GitHub의 **`.github/workflows/` 경로에 덮어쓰기** 합니다. 웹사이트 루트에 두지 마세요.
3. `Actions → Daily OHLCV and F9-A iPhone Signals → Run workflow`를 한번 실행합니다. `Tests` → `Refresh` → `Commit refreshed public data`가 모두 성공해야 데이터 JSON 4개가 바뀝니다.
4. 저장소 **Settings → Pages**에 GitHub Pages가 기존 `main / (root)`에 연결돼 있는지 확인합니다.
5. 아이폰 Safari에서 사이트에 방문한 뒤 새로고침합니다. 기존 홈 화면 앱은 서비스워커를 교체하도록 설계했으나 변경이 안 보이면 앱을 완전히 닫고 다시 열어 주세요.

## 테스트

```bash
python -m pip install 'yfinance>=0.2.65,<2' 'pandas>=2.2,<3' 'numpy>=1.26,<3'
python -m unittest test_signal_snapshot.py test_backtest_f_v9.py -v
python update_data.py
```

개편 소스만 업로드하면 **구버전 `data/*.json`에는 아직 `strategy`가 없으므로** 모바일에 `기존 데이터 → GitHub Actions 실행 필요`가 표시되는 것이 정상입니다. 데이터 작업을 수동 실행해야 F9-A 신호가 화면에 표시됩니다.

## 중요 제한

정적 GitHub Pages 자체가 사용자의 증권사 계좌나 시세 제공사의 실시간 스트리밍과 연결되는 것은 아닙니다. 모두 연구용 일봉 데이터 기반입니다. `yfinance` 데이터에는 분할 조정, 배당, 데이터 지연/누락과 라이선스 조건 문제의 가능성이 있고, 계산에는 수수료 0.1% 편도만 가정합니다. 슬리피지, 세금, 환율, 주문 최소 단위와 실계좌 수량 등은 반영되지 않습니다. F9 전략은 과거 데이터 탐색 연구이므로 과거 수익률과 신호의 미래 재현을 보장하지 않습니다.
